## Day 1

# 데이터의 특성
- 데이터 = 객곽적 사실 (존재적 특성)
- 정보 = 가공된 자료 (당위적 특성)

# 정성적 데이터와 정량적 데이터
- 정성적 데이터 = 언어, 문자 등
- 장량적 데이터 = 수치, 도형, 기호 등

# 정형 데이터, 비정형 데이터, 반정형(semi-structured) 데이터
- 정형 데이터 = 정형화된 틀 O, 연산 O (CSV, 엑셀)
- 비정형 데이터 = 정형화된 틀 X, 연산 X (소셜데이터, 댓글, 영상, 음성)
- 반정형 데이터 = 어느정도 형태가 존재, 연산 X (XML, JSON, 센서 데이터)

# 암묵지와 형식지
- 암묵지 = 겉으로 드러나지 않는 상태의 지식
- 형식지 = 외부로 표출돼 여러 사람이 공유할 수 있는 지식
  
@ 공통화, 표출화, 내면화, 연결화

# DIKW 피라미드
- 데이터 = 의미가 중요하지 않은 객관적인 사실
- 정보 = 데이터의 가공, 처리로 의미가 도출된 것
- 지식 = 다양한 정보를 구조화하여 고유의 지식으로 내재화된 것
- 지혜 = 지식의 축적과 아이디어가 결합된 창의적 산물

# 데이터의 단위
- bit-byte-KB-MB-GB-TB-PB-EB-ZB-YB

# 데이터베이스
- 여러 사람이 공유하여 사용할 목적으로 체계화해 통합, 관리하는 데이터의 집합이다.

# 데이터베이스의 일반적인 특징
- 통합된 데이터 = 동일한 내용의 데이터가 중복되어 있지 않다.
- 저장된 데이터 = 컴퓨터 매체가 접근할 수 있는 저장 매체에 저장되어 있다.
- 공용 데이터 = 여러 사용자가 공유할 수 있다.
- 변화하는 데이터 = 항상 최신의 정확한 데이터를 유지해야 한다.

# 데이터베이스의 다양한 측면에서의 특성
- 정보의 축적 및 전달 측면[^1]
- 정보이용 측면[^2]
- 정보관리 측면[^3]
- 정보기술발전 측면[^4]
- 경제, 산업적 측면[^5]

# 트랜잭션
- 정보처리 과정의 가장 작은 단위

# 데이터베이스 트랜잭션 특성
- 원자성[^6], 일관성[^7], 고립성[^8], 지속성[^9]

# 기업 내부의 데이터베이스
- 인하우스 DB = 기업 경영 전반에 관한 모든 자료를 연계 → ERP
- OLTP(Online Transaction Processing) = 정보 수집, 조직 내 공유 목적
- OLAP = 정보의 수집, 공유에서 탈피. 분석이 중심이 되는 시스템 구축
- CRM(Customer Relationship Management, 고객 관계관리)
- SCM(Supply Chain Management, 공급망관리)
- EAI(Enterprise Application Integration) = 모든 서비스를 중앙에서 관리하여 연결 루트를 간소화
- KMS(Knowledge Management System, 지식경영시스템)
- ERP(Enterprise Resource Planning, 경영자원통합관리)
- BI(Business Intelligence)
- RTE(Real Time Enterprise)

# 사회기반구조로서의 데이터베이스
- 물류 = CALS(Commerce At Light Speed), PORT-MIS(항만운영정보시스템), KROIS(철도운영정보시스템)
- 지리 = GIS(지리정보시스템), LBS(위치정보시스템), SIM(공간정보관리시스템)
- 교통 = ITS(지능형교통정보시스템)
- 의료 = PACS, U-Health
- 교육 = NEIS(교육행정정보시스템)

# 데이터베이스의 종류
- 관계형 DBMS(RDB) = Oracle, MySQL, DB2, Mariadb, Derby, SQLite
- NoSQL = CouchDB, MongoDB, 엘라스틱서치, Clouding, Dynamo, 레디스, BIgtable, HBase
- 계층형 DBMS
- 네트워크 형 DBMS
- 분산형 DBMS
- 객체지향 DBMS

# 데이터베이스 구성 요소
- 메타데이터 = 데이터를 설명하는 데이터
- 인덱스 = 신속하게 응답하고, 정렬하고, 탐색할 수 있도록 도와주는 색인 역할


# 데이터 마트(DM)와 데이터 웨어하우스(DW)
- 데이터 마트 = DW로부터 추출된 작은 데이터베이스. 특정 목표를 달성하는데 필요한 데이터를 제공
- 데이터 웨어하우스 = 총체적인 관점에서 의사결정을 위해 공통의 형식으로 변환해 관리하는 역할. 데이터베이스의 집합체


# 빅데이터 정의
- 노무라연구소 정의 = 데이터 + 인재와 조직
- 더그 래니(3V) = 양(Volume), 다양성(Variety), 속도(Velocity)

# 더그 래니의 3V
- 데이터의 양의 증가
- 데이터 유형 증가
- 데이터 수집 및 처리 속도의 증가

# 빅데이터의 새로운 특징 4V
- 3V + 가치(Value) or 정확성(Veracity) or 시각화(Visualization) or 가변성(Variability)

# 빅데이터의 출현 배경
- 데이터의 양적 증가 (ZB 본격화 시대)
- 산업계의 변화
- 학계의 변화
- 관련 기술의 발전

# 빅데이터의 기능
- 빅데이터는 산업혁명의 석탄, 철
- 빅데이터는 21세기 원유
- 빅데이터는 렌즈
- 빅데이터는 플랫폼

# 빅데이터가 만들어내는 변화
- 사전처리 → 사후처리
- 표본조사 → 전수조사
- 질 → 양
- 인과관계 → 상관관계

{: data-content="footnotes"}

[^1]: 정보의 축적 및 전달 측면 (1. 기계가독성 : 일정한 형식에 따라 컴퓨터 등의 정보처리기기가 읽고 쓸 수 있음. 2. 검색가독성 : 다양한 방법으로 필요한 정보를 검색. 3. 원격조작성 : 정보통신망을 통하여 원거리에서도 즉시 온라인을 이용)

[^2]: 정보 이용 측면 : 이용자의 정보 요구에 따라 다양한 정보를 신속하게 획득,  원하는 정보를 정확하고 경제적으로 찾아낼 수 있다는 특성

​[^3]: 정보 관리 측면 : 정보를 일정한 질서와 구조에 따라 정리, 저장, 검색, 관리 할 수 있도록 하여 방대한 양의 정보를 체계적으로 축적하고 새로운 내용의 추가나 갱신이 용이

[^4]: 정보기술 발전 측면 : 데이터 베이스는 정보처리, 검색-관리 소프트웨어, 관련 하드웨어, 정보 전송을 위한 네트워크기술의 발전을 견인할 수 있음.

[^5]: 경제-산업 측면 : 다양한 정보를 필요에 따라 신속하게 제공-이용할 수 있는 인프라로서 특성을 가지고 있어 경제, 산업, 사회 활동의 효울성을 제고하고 국민의 편의를 증진하는 수단으로서 의미를 가짐.

[^6]: 원자성 : 트랜잭션이 데이터베이스에 전부 작용되거나, 그렇지 않다면 전부 적용되지 않는 특징

[^7]: 일관성 : 작업 처리 결과에는 언제나 일관성이 있어야 한다는 특징. (예시. 시험 점수가 0~100점이라고 가정할 때, 트랜잭션에서 a학생의 성적을 110점이라고 기록하면 일관적지 않고, 예외적이기 때문에 트랜잭션은 처리되지 않고 거부된다.)

[^8]: 독립성 : 2개 이상의 트랜잭션이 동시에 움직이는 경우 절대 서로의 연산에 개입하지 않는다는 특징

[^9]: 지속성 : 성공적으로 끝난 트랜잭션 작업 결과는 영구적으로 반영된다.
